# Application Documentation Index

This directory contains policy and pattern documentation for the Antkeeper workflow framework.

## Files

- **reference.md** - Comprehensive reference guide covering project structure, core concepts in detail, writing handlers (decorator pattern and cc_handler factory), LLM integration, git utilities, data flow for all channels (CLI, API, Slack), logging and state persistence, CLI commands, and codebase navigation. This is where readers go after the main README for detailed technical reference.

- **releasing.md** - Packaging, dependency management, and PyPI release process. Covers the split dependency model (core vs optional dependencies), public API exports, entry points (CLI script and Python module), environment variables (`ANTKEEPER_HANDLERS_FILE`), package metadata, build system (uv_build), release checklist, publishing to PyPI, post-release verification, and version numbering strategy. Documents how Slack functionality (httpx) is a core dependency, while server features (FastAPI, uvicorn) are optional extras.

- **testing_policy.md** - Testing approach, fixture management, test structure rules, and test organization. Covers how to write tests for the framework core, including the `app` fixture for log, worktree, and state isolation, the `git_repo` fixture for all git tests (command execution, branch operations, worktrees), patterns for testing git command execution (`execute()` with stdout/stderr/empty output), branch operations (`current()` with default/switched/detached branches), git worktrees, and state persistence, CLI testing patterns (argument parsing vs integration tests with positional file arguments; `_build_parser()` mirrors the production parser structure including the shared parent parser pattern for `run` and `fix-gh-issues`), resume testing patterns (`tests/core/test_resume.py` for `_load_state_by_run_id`, `TestWorkflowSkip` for `run_workflow` skip/`_resume_skip` behaviour, `TestResumeArgParsing` and `TestResumeIntegration` in `test_cli.py`), API channel testing patterns (ApiChannel unit tests with FastAPI TestClient), SlackChannel testing patterns (mocking httpx), Slack server testing patterns (AsyncMock, env patching, deterministic timers, and the `slack_client_no_env` fixture pattern for testing without environment variables by popping vars after `create_app()` to handle dotenv loading), App environment variable testing patterns (`TestAppEnvironment` class: env var setting, str conversion, restoration after success/failure, existing-var preservation, no-op for None/empty, invalid conversion propagation, and visibility to `run_workflow()` steps), `TestWorkflowProgress` patterns (`_progress` tracking: final state, per-step increment, pre-first-step disk persistence via `runner._state_path`, and absence for direct `Runner.run()` calls), LLM agent testing patterns (`_envelope()` helper for mock subprocess stdout, `TestJsonOutputMode` class for JSON parsing and telemetry tests, `caplog` usage for debug-level telemetry assertions), and handler factory testing patterns (mocking `run_prompt` and `extract_json` at the factory module, `runner_factory()` with no arguments, validation tests without Runner, error handling with `WorkflowFailedError`).

- **instrumentation.md** - Progress reporting, error handling (including `WorkflowFailedError`), run identification, logging patterns, automatic state persistence, workflow resume mechanics, and git integration. Explains the Channel interface for I/O (CliChannel, ApiChannel, SlackChannel), how handlers communicate status, per-run file-based logging (including callable `log_dir` support for dynamic per-handler log directories and `make_log_dir()` as the standard helper for producing timestamped per-run directories), callable `env` values for dynamic per-handler environment variable resolution, automatic JSON state persistence with correlation to log files (four persistence points: initial state, before first workflow step with `_progress` initialized to `completed: skip`, after each workflow step, and final state), the workflow resume mechanism (`_resume_skip` one-shot signal, skip logic in `run_workflow`, new run_id per resume, original state file not modified), error handling differences between CLI and API execution, the `cc_handler` factory (fire-and-forget mode and extraction mode — two sequential `run_prompt` calls where Step 1 sends the raw prompt to the configured model and Step 2 sends an extraction prompt to haiku to parse structured JSON fields, optional `model` override to pin a specific LLM model per handler for Step 1, optional `env` dict for per-handler environment variable overrides that merge with App-level env using handler-wins semantics and are restored after handler completion, label/`__name__` derivation, `$var` command interpolation, standardised error handling via `runner.fail()`, when to use factory vs hand-written handlers, and `app.add_handler()` registration), the `ClaudeCodeAgent` class for LLM integration (JSON output mode, `--output-format json` flag injection, per-call telemetry logging at DEBUG level — `session_id`, `duration_ms`, `usage`, `total_cost_usd` — Claude session transcript location at `~/.claude/projects/<project>/<session_id>.jsonl`, model selection, yolo mode, arbitrary CLI options, and the `AgentExecutionError` / `ValueError` error taxonomy), git command execution via `execute()`, branch operations via `current()`, `GitCommandError` exception handling, the `Worktree` class for git worktree operations, the `git_worktree` context manager for cwd restoration guarantees, and worktree naming conventions (using `make_timestamp()` for correlation with log files).

- **http_server.md** - HTTP server architecture and endpoint design. Covers the standard FastAPI pattern in `server.py` (routes defined with `@api.post()` decorators), the `http/__init__.py` module exporting `run_workflow_background()` to break circular imports, `webhook.py` exporting `handle_webhook()` function, `slack_events.py` exporting `SlackEventProcessor` class with explicit state management, background task execution patterns, the factory pattern in `create_app()`, and POST `/slack_event` environment variable validation (HTTP 422 when `SLACK_BOT_TOKEN` or `SLACK_BOT_USER_ID` missing, with `url_verification` exception).

- **slack.md** - Slack integration: app configuration (bot token, user ID), event handling via POST `/slack_event`, required environment variables (`SLACK_BOT_TOKEN`, `SLACK_BOT_USER_ID`) with validation behavior (HTTP 422 for missing vars, `url_verification` bypass), the `SlackEventProcessor` class managing debounce state, debounce logic for rapid @mentions (`SLACK_COOLDOWN_SECONDS`), `PendingMessage` dataclass, event routing order (thread replies, edits, deletes, mentions), `SlackChannel` for thread-based replies, timer reset behavior, and environment variable setup (`.env` support).

## Usage

The main [README.md](../README.md) introduces the framework concepts and provides a quickstart.

**reference.md** is the detailed technical reference — start here if you want to understand how to write handlers, compose workflows, or use the CLI and API.

The remaining docs describe **framework internals and policies for extending them**. If you're writing framework code (in `src/antkeeper/core/`, `src/antkeeper/channels/`, `src/antkeeper/http/`, or `src/antkeeper/llm/`), read these docs.

If you're writing application handlers, start with the main README and the reference guide.
